UamiShop

Transformación: De Monolito a Microservicios

Un viaje por la arquitectura moderna, desde el Diseño Guiado por Dominio hasta la arquitectura escalable de microservicios.

Reto Principal

Desacoplar la lógica de negocio y garantizar la consistencia en un entorno distribuido.

Metodología

Evolución iterativa basada en DDD, Monolito Modular y Extracción por Bounded Contexts.

Fase 1: Fundamentos

Diseño Guiado por Dominio (DDD)

Establecimos los cimientos del proyecto utilizando Bounded Contexts y el Shared Kernel.

1Identificamos los contextos de Catálogo, Ventas y Ordenes.
2Definimos el Shared Kernel (Money, IDs) para cruzar fronteras.
3Implementamos API REST con versionamiento v1/v2.

Logro

Un modelo de negocio robusto que guía la estructura técnica, no al revés.

Fase 2: Monolito Modular

Encapsulamiento y APIs Internas

Transformamos el sistema en un monolito modular para preparar la extracción de microservicios.

Ocultamiento de Información

Cada módulo expone una interfaz pública única (VentasApi), ocultando su implementación interna.

Dependencias Controladas

Las interdependencias entre módulos se resuelven a través de servicios del Shared Kernel y DTOs específicos.

Fase 3: Microservicios

Despliegue con Docker y Orquestación

Extrajimos los módulos hacia contenedores independientes, escalables de forma individual.

  • 🔹 uamishop-catalogo: Puerto 8081
  • 🔹 uamishop-ordenes: Puerto 8082
  • 🔹 uamishop-ventas: Puerto 8083
  • 🔹 uamishop-gateway: Puerto 8080

Docker Compose

Orquestación local con bases de datos segregadas y redes aisladas.

Resiliencia

Patrones con Resilience4J

Implementamos tolerancia a fallos para asegurar que una caída parcial no afecte a todo el sistema.

Circuit Breaker

Si el servicio de Catálogo está inactivo, el servicio de Ventas devuelve un 503 Service Unavailable controlado con un mensaje significativo, evitando que los hilos de ejecución se bloqueen.

@CircuitBreaker(name = "catalogoService")

Consistencia Distribuida

Transactional Outbox Pattern

Garantizamos que los eventos y las actualizaciones en la base de datos sean atómicos.

El OutboxPublisher procesa eventos pendientes y asegura el "Delivery At-least-once".

Pruebas y UI

Testing con Karate y Frontend IA

Aseguramos la calidad del API y una experiencia de usuario moderna.

Karate Testing

Pruebas automatizadas de extremo a extremo (E2E) a través del API Gateway.

Frontend Moderno

Potenciado por Vite y React, con un diseño estético y consumo dinámico de microservicios.

Lecciones Aprendidas

Conclusiones del Proyecto

Reflexión sobre el proceso de ingeniería de software.

  • ✅ La modularización es el paso previo esencial antes de la distribución física.
  • ✅ El desacoplamiento no es gratuito; requiere patrones de consistencia y resiliencia.
  • ✅ Las herramientas como Docker agilizan dramáticamente el despliegue y desarrollo local.
  • ✅ La documentación (OpenAPI/Swagger) y pruebas integradas son la columna vertebral de la colaboración.
